# KYOZAI 公開体験版 実装・検証報告書

作成日: 2026-08-12  
公開URL: https://kyozai-v1.vercel.app

## 1. 結論

見込み客がPC・スマートフォンから利用できる公開体験版を先行公開した。中核機能は
デモ表示ではなく実OpenAI APIで動作し、資料投入から教材一式の完成、自然言語による修正、
HTML納品までを完走できる。

KYOZAIは一般的なスライド編集APPへ寄せず、「資料を入れる、完成する、そのまま使う」を
主経路とした。手動編集機能の充実は優先せず、初回完成度とAI修正の信頼性を優先している。

## 2. 完成機能

| 区分 | 内容 | 状態 |
|---|---|---|
| 入力 | PDF、TXT、Markdown、URL、直接入力 | 実動 |
| 生成 | スライド、講師シナリオ、FAQ、ミニテスト | 実動 |
| AI修正 | 自然言語指示で教材一式を修正 | 実動 |
| 修正検証 | 別AIで達成判定、未達時に再修正 | 実動 |
| 出力 | 自己完結HTMLの閲覧・印刷・保存 | 実動 |
| UI | PC・スマートフォン対応 | 実動 |
| 共通デザイン | Skill/APPとも`kyozai-standard@1.0.0`を使用 | 実動 |
| 安全策 | 形式・容量検証、URL制限、基本レート制限 | 実動 |

AI修正は生成JSONを単に置き換えるだけではなく、完全な構造検証、独立した達成評価、
必要時のrepairを通す。最終評価に失敗した場合は、画面上の元教材を維持する。

## 3. 開発中機能

以下は未完成であり、完成機能として扱わない。該当UIには「開発中」を表示する。

- 画面を閉じても続くバックグラウンド生成
- ログイン、履歴、案件の再開、端末間同期
- 版管理、差分表示、rollback
- PowerPoint・Wordの直接入力
- PPTX、PDF、PNG、ZIPの正式出力
- 高度な手動スライド編集

## 4. 検証結果

| 検証 | 結果 |
|---|---|
| 公開ページ | HTTP 200、正しい見出し |
| ヘルスチェック | HTTP 200、status ok |
| セキュリティヘッダー | CSP、frame deny、nosniffを確認 |
| 本番AI生成 | 6スライド、FAQ 4件、テスト3問を生成 |
| 本番AI修正 | タイトル・初心者向け表現の修正に成功 |
| 本番PDF入力 | 汎用MIMEのブランド設計PDFから8スライド、シナリオ6区分、FAQ 6件、テスト4問を生成 |
| TypeScript | 成功 |
| ESLint | 成功 |
| 単体テスト | 16件成功。profile同一性、全7 layout、途中JSONの安全化を含む |
| Next.js production build | 成功 |
| Playwright desktop/mobile | 3件成功 |
| レスポンシブ表示 | desktop/mobileとも横スクロールなし |

本番AI検証には一般的な架空の情報セキュリティ研修文を用い、生成結果の内容・件数のみを
確認した。APIキーの値や利用者の資料はGit・報告書へ保存していない。

公開後にOpenAI応答が途中終了し、JSON parserのエラーが利用者へ表示される事象を確認した。
応答完了状態の検査、出力上限の拡大、自動再試行、人間向けエラーへの置換を追加して再配備した。
修正後の本番実生成は正常に完走している。

その後、APPの教材デザインへ正本Skillの詳細規則が接続されていない問題を修正した。共通profile、
内容別layout family、表紙/CTA、比較labelsをSchemaに追加し、プレビューとHTMLを同じ白・黒・青の
レンダラーへ変更した。3つのprofile mirrorは単体テストで同一性を検査する。

独立レビューで当初、deck-spec項目、具体構図、APP/HTML差、ブラウザーJSON解析、API時間上限、
runtime検証の不足が指摘された。修正後の再レビューでは公開停止相当の未解消P1なしと判定された。

最終本番検証では共通profileによる7 layoutの生成を77秒で完了した。続くAI修正でもprofileと
layout familyを維持したまま、タイトル修正へ成功した。

## 5. 独立検証

サブエージェントに、参考UI、ブランド方針、実装を独立レビューさせた。主な指摘は、固定進捗が
実処理に見える点、出力が弱い点、Schema検証の深さ、修正の影響範囲、スマートフォン試験、
本番mock混入リスクだった。

公開前に固定進捗を廃止し、HTML納品、完全な構造検証、修正評価とrepair、mobile中核フロー試験、
productionでE2E mockを無効化するガードを実装した。永続job・履歴・rollbackは未完成として残した。

## 6. 残存リスク

- 同期生成のため、処理中にページを閉じると再開できない。
- レート制限はプロセス内のbest-effortであり、複数instanceを横断しない。
- URL入力の防御はプライベートIP・redirect・容量等を検査するが、公開体験版で機密URLを扱わない。
- AI修正は評価・repairを入れているが、全指示の完全保証には評価セットと版rollbackが必要。
- 現在の納品形式はHTMLであり、PPTX等が必要な顧客には不足する。

## 7. 次期優先順位

最優先は、永続job・履歴・再開である。これにより「どこでもいつでも」と「画面を閉じても完成」を
実現する。次にAI修正の版管理・rollback、正式なPDF/PNG/ZIP出力を追加する。PPTXは顧客検証後に
最低限の納品互換機能として実装し、高機能編集APP化は行わない。
