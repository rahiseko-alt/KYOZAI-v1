# in / out

引数が `in` か `out` かで分岐する。引数が無ければユーザーに聞く。

## in（開始）

1. `docs/handoff.md` を読む。**無い、または AGENTS.md に「未記入」が残っている**なら初期設定が
   済んでいないので `setup` を実行する（`setup` は、ルール自体を直す回ならすぐ終わる）。
2. ①〜③を2〜3行でユーザーに伝える。
3. 作業中のブランチがあればそのまま使う。無ければ main（プロダクトが別ブランチにあるならそちら）から作る。
4. ③（次回やること）を今回の作業案として出す。ユーザーが別のことを言えばそちらを優先する。

## out（終了）

1. `docs/handoff.md` を今回の内容で上書きする。前回分は消す。
2. 失敗があれば `docs/failures.md` に1件追記する。既存行は消さない。
3. コミットして push する。**ここで終わり。**

**PR とマージは「PR 出して」「マージして」と言われたときだけ**。毎回は作らない。聞きもしない。
言われたときは、PR を作り CI が緑になったらマージし、ブランチを削除する。赤なら直す。

マージを一時保留したい PR にだけ `hold` ラベルを付ける（auto-merge を止める）。それ以外では使わない。

引継ぎに書かないもの: 恒久的なルール（AGENTS.md に書く）、失敗の記録（`docs/failures.md`。handoff は上書きされて消える）、進捗の詳細（コミット履歴にある）。
